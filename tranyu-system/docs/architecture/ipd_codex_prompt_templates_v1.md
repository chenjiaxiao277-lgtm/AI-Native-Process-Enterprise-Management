# IPD 项目 Codex 协作提示词模板（v1）

## 1. 使用原则

为了减少上下文膨胀、避免跨项目信息串线、提高连续开发效率，后续与 Codex 协作时统一采用“基线 + 阶段 + 范围 + 要求 + 验收”的短提示词格式。

默认规则：

- 所有需求默认基于 `IPD 项目架构基线（v2）`
- 优先引用现有文档，不重复粘贴长背景
- 一次只推进一个阶段中的一个小任务
- 如无特殊说明，默认不跨项目、不引入 LTC 基线要求

相关基线文档：

- `docs/architecture/ipd_architecture_baseline_v2.md`
- `docs/architecture/rectification_execution_plan_20260327.md`
- `docs/architecture/ipd_tenant_scalability_preparation_plan_v1.md`

---

## 2. 标准提示词结构

推荐统一使用下面的结构：

```text
按 IPD 项目架构基线（v2）继续。

执行：
- Phase X 第 Y 项

范围：
- 只改哪些目录/模块
- 不改哪些模块

要求：
- 需要落哪些内容（SQL / 实体 / mapper / service / 前端页面 / 文档）
- 是否要求编译通过
- 是否要求更新计划文档

验收：
- 需要我如何验证
```

## 3. 可直接复制使用的提示词模板

### 模板 A：继续下一步

```text
按 IPD 项目架构基线（v2）继续。
按整改计划执行下一步。

要求：
- 先看现有代码风格再改
- 改完后告诉我改了哪些文件
- 更新对应架构计划文档
```

### 模板 B：执行某个阶段中的一个小任务

```text
按 IPD 项目架构基线（v2）继续。

执行：
- Phase B 第 1 项

范围：
- 只改 tranyu-backend
- 不改 tranyu-frontend

要求：
- 落库脚本 + 实体 + mapper + service
- compileJava 通过
- 把进度写回 rectification_execution_plan_20260327.md
```

### 模板 C：只做后端

```text
按 IPD 项目架构基线（v2）继续。

本次只做后端，不动前端。

要求：
- 只修改 tranyu-backend
- 不改接口返回结构
- 改完后做编译验证
```

### 模板 D：只做前端

```text
按 IPD 项目架构基线（v2）继续。

本次只做前端页面接入。

范围：
- 只改 tranyu-frontend
- 不改后端逻辑

要求：
- 页面与现有风格一致
- 保留现有交互
- 告诉我如何手工验证
```

### 模板 E：先评估再实施

```text
按 IPD 项目架构基线（v2）继续。

先不要写代码，先评估下面这项改造是否合理：
- （这里写需求）

输出：
- 风险点
- 对架构的影响
- 推荐实施顺序
```

### 模板 F：只更新方案或计划，不写代码

```text
按 IPD 项目架构基线（v2）继续。

本次不写代码，只做文档更新。

要求：
- 更新架构基线
- 更新整改计划
- 增加本次任务的执行清单与验收项
```

### 模板 G：执行数据库迁移

```text

- 当前阶段涉及的 SQL 迁移

要求：
- 先生成迁移脚本
- 再说明迁移影响
- 如果需要执行数据库变更，明确告诉我验证方式
```

### 模板 H：补测试用例

```text
按 IPD 项目架构基线（v2）继续。

针对刚刚完成的改造，补一份测试用例文档。

要求：
- 覆盖正常流
- 覆盖越权场景
- 覆盖跨空间/跨租户场景
- 保存到 docs 下
```

### 模板 I：修复回归问题

```text
按 IPD 项目架构基线（v2）继续。

修复一个回归问题：
- （这里写报错现象）

要求：
- 先定位原因
- 再做最小改动修复
- 不顺手改无关模块
- 最后告诉我根因和验证方式
```

### 模板 J：执行背景刷新

```text
执行背景刷新。
按当前架构文档重新收口上下文，并继续最近的计划项。
```

适用场景：

- 你感觉我开始串项目
- 对话太长，担心上下文不稳定
- 中断了一段时间后继续

## 4. 推荐对话方式

为了保证稳定性，建议采用下面的协作节奏：

1. 你一次只发一个任务
2. 我完成后返回：
   - 当前完成内容
   - 修改文件列表
   - 验证方式
   - 下一步建议
3. 你再决定继续哪一项

不推荐的方式：

- 一次性塞很多需求
- 混入多个项目背景
- 同时要求前后端、数据库、架构、测试全部一起改
- 不说明范围就直接让我大改

---

## 5. 提示词里的关键信息优先级

如果你想压缩提示词，优先保留下面 5 项：

1. 基于哪份架构基线
2. 执行哪个 Phase / 哪一项
3. 本次只改哪里
4. 本次不要改哪里
5. 验收标准是什么

最短可用版示例：

```text
按 IPD 项目架构基线（v2）继续。
执行 Phase F 第 3 项。
只改后端，不改前端。
要求 compileJava 通过，并更新整改计划。
```
