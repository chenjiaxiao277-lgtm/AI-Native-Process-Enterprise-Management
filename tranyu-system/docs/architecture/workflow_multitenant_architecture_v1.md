# LTC 多租户 + Flowable 架构补充方案（v1）

> 废弃说明：该文档保留历史参考，不再作为当前实现基线。

## 1. 目标与边界

### 1.1 目标
- 构建企业级多租户 B 端流程系统，支持大规模配置与稳定执行。
- 前端体验对齐飞书项目风格，流程执行内核统一由 Flowable 6.8.1 承担。
- 业务层实现强租户隔离、强权限控制、强审计可追溯。

### 1.3 多租户层级（核心定义）
- **一级：租户（tenant）**，对应企业组织边界。
- **二级：空间（space）**，一个租户下可有多个空间。
- **三级：业务对象**（工作项类型、工作项实例、流程模板、流程实例、任务等）归属某个空间。
- 默认访问范围为“当前租户 + 当前空间”，跨空间访问必须经过“空间关联授权”。

### 1.2 明确边界
- **不自研流程引擎**，不替代 Flowable 执行能力。
- **不改 Flowable act_* 表结构**，不依赖 Flowable UI。
- 流程定义、权限、可见性、隔离策略都在业务层处理。

## 2. 分层架构（补强）

1. 业务应用层
- Controller / Service / DTO / VO。
- 对外统一 API（不暴露 Flowable 原生 API）。

2. 业务流程层
- 自定义流程模板、节点模型、节点行为（通过/驳回/加签/转办/撤回）。
- 任务权限、可见范围、节点规则。

3. 适配转换层
- 自定义节点流模型 -> BPMN XML（内存生成、动态部署）。
- Flowable 回调/任务事件 -> 业务事件模型。

4. 引擎执行层
- Flowable 仅负责 token 流转、任务生命周期、历史记录。

## 3. 多租户隔离设计（必须项）

### 3.1 数据隔离
- 所有业务表必须有 `tenant_id`（含模板、节点、实例、任务、评论、角色、表单配置等）。
- 空间级业务表必须额外有 `space_id`（工作项、流程模板、流程实例、任务、页面布局、角色配置等）。
- 所有查询/更新/删除默认强制附加 `tenant_id + space_id` 条件（空间级数据）。
- 禁止业务 SQL 绕过租户条件（含自定义 SQL 与批量脚本）。

### 3.2 上下文传递
- `TenantContext` 从登录态/JWT/网关头提取。
- 在请求入口（过滤器/拦截器）写入上下文，请求结束清理上下文。
- 异步任务必须显式透传或恢复 `tenant_id`。

### 3.3 Flowable 隔离策略
- act_* 表不存 `tenant_id`，通过业务映射表关联 Flowable 实例 ID。
- 业务映射表必须携带 `tenant_id + space_id`，并作为所有流程查询的第一过滤条件。
- 查询待办/已办先从业务域确定“当前租户 + 当前空间”可见范围，再向 Flowable 拉取任务，再二次过滤合并。

### 3.4 空间关联与授权
- 默认：同租户不同空间数据互不可见。
- 允许跨空间访问时，必须在“空间关联”中建立授权关系（来源空间、目标空间、可访问资源、有效期、授权人）。
- 跨空间查询必须附加授权校验，不可直接放开 `space_id` 条件。

## 4. 流程模型约束（防止后期失控）

### 4.1 自定义节点模型最小闭集
- `START`, `APPROVAL`, `CC`, `CONDITION`, `PARALLEL`, `END`。
- 审批处理模式：`SINGLE`, `OR_SIGN`, `COUNTER_SIGN`（多实例）。

### 4.2 行为约束
- 驳回可指定目标节点，但必须满足“可达性 + 权限 + 节点状态一致性”。
- 任意跳转/加签/转办/撤回需要业务白名单策略与审计记录。
- 所有行为必须有幂等键（避免重复提交）。

### 4.3 BPMN 生成约束
- 仅允许受控节点类型映射，禁止前端直接上传任意 BPMN。
- 部署前执行结构校验：无环死路、必有开始结束、条件完整覆盖。

## 5. 风险清单与治理策略（重点）

1. 风险：跨租户数据泄露
- 治理：统一租户拦截 + Mapper 自动注入 + SQL 审计扫描 + 集成测试（跨租户越权用例）。

1.1 风险：同租户跨空间数据串读
- 治理：空间上下文强制注入 + 默认 `space_id` 过滤 + 空间授权白名单校验。

2. 风险：流程动作越权（驳回/跳转）
- 治理：动作策略中心（Policy Service）统一判定；禁止在 Controller 内写权限分支。

3. 风险：业务状态与 Flowable 状态不一致
- 治理：事务边界统一；关键动作采用 outbox/event 补偿；失败自动重试与告警。

4. 风险：流程模板升级破坏在途实例
- 治理：模板版本化（不可覆盖发布）；实例绑定版本；灰度发布。

5. 风险：会签并发导致重复审批
- 治理：乐观锁/版本号 + 幂等令牌 + 任务完成前二次校验。

6. 风险：复杂查询性能下降
- 治理：业务表按 `tenant_id + status + create_time` 建组合索引；分页与归档分层。

7. 风险：动态 BPMN 生成错误
- 治理：生成前校验 + 可视化预览 + 流程模拟执行（dry run）。

8. 风险：审计不可追溯
- 治理：统一操作日志（人/租户/动作/前后值/时间/IP/来源端）。

9. 风险：后期“偷偷自研引擎”扩散
- 治理：架构守卫规则：禁止实现 token 引擎语义，所有执行行为必须委托 Flowable API。

## 5.1 风险分级矩阵（上线前必须评审）

| 风险项 | 概率 | 影响 | 优先级 | 强制措施 |
| --- | --- | --- | --- | --- |
| 跨租户数据泄露 | 中 | 极高 | P0 | 租户注入 + SQL 扫描 + 越权回归用例门禁 |
| 同租户跨空间串读 | 中 | 高 | P0 | space_id 强制过滤 + 空间授权白名单 |
| 流程动作越权 | 中 | 高 | P0 | Policy Service 统一鉴权 + 审计必填 |
| 业务状态与引擎状态不一致 | 中 | 高 | P0 | 事务边界 + outbox 补偿 + 重试告警 |
| 模板升级影响在途实例 | 中 | 高 | P1 | 模板版本化 + 灰度发布 + 回滚策略 |
| 会签并发重复处理 | 中 | 中高 | P1 | 幂等键 + 乐观锁 + 二次状态校验 |
| 动态 BPMN 生成不合法 | 低中 | 高 | P1 | 结构校验 + dry run + 回归样例 |
| 查询性能退化 | 中 | 中 | P2 | 复合索引 + 分页策略 + 冷热分层 |

## 5.2 失败兜底策略（必须实现）

- 流程启动失败：业务实例标记 `FAILED`，记录失败原因，可人工重试。
- 审批动作失败：采用幂等令牌，重试不重复推进流程。
- 引擎不可用：业务侧降级为“只读 + 告警”，禁止继续提交流程动作。
- 回调异常：进入死信队列/补偿任务，后台可重放。
- 模板发布异常：自动回滚到最近可用版本。

## 6. 非功能要求（NFR）
- 可用性：关键流程 API 99.9%。
- 一致性：核心状态变更必须事务一致或最终一致（具备补偿）。
- 安全性：租户越权 0 容忍，关键接口必须权限 + 租户双校验。
- 可观测：流程启动、完成、异常、重试、超时全量埋点。

## 7. 落地顺序（建议 4 阶段）

### 阶段 A：隔离地基
- TenantContext、租户拦截器、租户自动注入、全局异常/返回。

### 阶段 B：流程主链路
- 模板管理、节点管理、BPMN 生成、启动/审批通过/待办已办。

### 阶段 C：复杂动作
- 驳回到指定节点、会签/或签、加签、转办、撤回。

### 阶段 D：治理增强
- 版本化、灰度、审计中心、性能优化、回归测试矩阵。

## 8. 代码规范补充（强约束）
- 禁止在 Controller 直接操作 Mapper。
- 禁止在业务 SQL 中写死 tenant_id。
- 禁止直接暴露 RuntimeService/TaskService 到 Controller。
- 所有流程动作服务必须可测试（单元 + 集成）。

## 9. 验收清单（上线前）
- [ ] 所有业务表已含 `tenant_id` 且有必要索引。
- [ ] 核心查询全覆盖租户条件。
- [ ] 流程动作幂等已实现。
- [ ] 关键动作审计日志完整。
- [ ] 跨租户越权测试通过。
- [ ] 流程模板版本升级不会影响在途实例。

## 10. 架构守卫（AI/研发共用）

以下规则作为“不可破坏约束”，后续所有需求开发必须满足：

1. 禁止 Controller 直接调用 Flowable 原生 Service。
2. 禁止在前端或 API 直接暴露 Flowable act_* 主键语义。
3. 禁止流程节点逻辑散落在 Controller/Mapper，必须收敛到流程服务层。
4. 禁止任何业务表缺失 `tenant_id`；空间级表禁止缺失 `space_id`。
5. 禁止编写未带 `tenant_id`（及空间级数据未带 `space_id`）条件的自定义 SQL。
6. 禁止通过“临时脚本”跨租户修改数据且不留审计。
7. 禁止以“性能优化”为由绕过权限和租户校验。

- [ ] 是否引入了同租户跨空间访问风险？是否有授权与回归测试？

- [ ] 是否补全了动作审计日志（发起/审批/驳回/转办/撤回）？
- [ ] 是否提供异常回滚或补偿机制？
